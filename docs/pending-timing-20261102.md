# Pending 分段计时恢复（2026-11-02）

为定位节点收到交易到 arb-engine 收到通知的耗时，在生产源码
`f83f4666ca6a886dcfff035db99da979b1dfe65a` 上恢复历史
`a919c9a..3e2e778` 的基础只读计时实现和修正测试。

只恢复基础 1/32 哈希采样、65,536 条边界事件内存环、
`debug_pendingTiming` 和离线分析器。没有恢复后来加入的全局锁/P2P
打点、价格堆优化、零 base-fee 比较或状态预加载；200ms 公告等待、
24 个模拟槽位、队列容量、交易准入和通知内容保持原有逻辑。

事件覆盖 hash/body 收到、解码、获取等待、入池锁等待与执行、promotion
调度、feed、订阅队列、模拟调度/执行/结果队列、组装、notifier 锁和
codec 写入。node 的 `notify_return` 不代表客户端已经收到。
arb-engine 提交 `5a3c404` 为相同 1/32 哈希增加完整 WS 帧可用和解码完成
的本机微秒时间，并记录真实 RPC subscription ID，供同机两端连接。

按 boot、hash、operation、subscription 和 attempt 关联。缺失、重复
或跨轮转丢失的边界保持未知；不能把 `tracker_first_seen` 当作网络到达，
不能累加相互重叠的阶段耗时，也不能把 block age 当作传输耗时。

验证：Go 1.25.0 / Linux CGO 下 8 个相关包的完整测试通过；离线分析器
8 项 Python 测试通过。Windows 无 CGO 的 BLS 构建失败和第一次 WSL
依赖下载超时均为环境失败，日志保留；使用已有本地模块缓存后通过。
同 8 包的计时、队列、采样和关联用例通过 `-race`。实际发布、测量结果
以后续验收记录为准。部署和采集脚本复用 2026-10-23 版本，新增当前提交
校验、运行环境保留及引擎收帧字段；采集只轮询诊断 RPC 和现有日志。

历史 [计时说明](pending-timing.md) 包含已撤回的扩展，不能把其完整事件
清单套到本次恢复的基础版；本次未恢复的事件不会出现在 RPC 中。
